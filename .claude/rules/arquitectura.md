# Arquitectura, stack y estructura (cargan al tocar la configuración de Next, `package.json` o `src/app/`)

Parte de la constitución de HackGuard (`CLAUDE.md`). Aquí vive el detalle de stack y estructura; no hay reglas numeradas.

- **Qué es, completo:** planeador, gestor y validador de pruebas de seguridad para software y sistemas de IA. Catálogo vivo de pruebas en cuatro familias (software · agente · modelo generativo · modelo de decisión tipado), cada una trazada a un marco con versión y, cuando se puede, a un control de ISO/IEC 42001; planea desde el perfil del activo con alcance autorizado; recibe resultados de herramientas externas como evidencia confirmada por una persona; mide la brecha control por control. Tesis: *un hallazgo no es una vulnerabilidad; es evidencia de que un control falla.* Fuentes de verdad (planeadora, RO): `portafolio/hackguard/brief.md` (manda sobre la especificación) · `VISION.md` · `investigacion/2026-10-02-especificacion-features.md` (E-1…E-29) · `corpus/raw/[APP HackGuard] - Requerimientos v1.1.md`.
- **Stack:** Next.js 16 **exportado estático** (`output: "export"`, `images.unoptimized`; `pnpm start` sirve `out/` con `serve`; la CI construye como el proveedor con `scripts/build-como-proveedor.mjs`) + TypeScript strict + Tailwind · **sin backend, sin base de datos, sin auth, sin IA en tiempo de ejecución** · datos como JSON versionados con huella (JCS RFC 8785 + SHA-256 con `crypto.subtle`) · Vitest + Playwright + Testing Library + @axe-core/playwright · Sentry client-only y metadata-only (inerte sin DSN) · Vercel con protección en **All Deployments** (la app privada no se muestra a nadie; la superficie pública del H-2 es el paquete estático dentro de hoja-de-vida). Node ≥ 22.18 (el CLI corre TypeScript nativo, sin `tsx`).
